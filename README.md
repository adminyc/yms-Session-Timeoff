# session-handoff-backup — 跨会话交接技能（Agent Skill）

把一次长会话压缩成一份「下一个会话的接管说明书」`TIMEOFF.md`，解决"对话太长、换个会话就丢上下文"的问题。

## 它解决什么问题

长会话结束时，下一个会话的人是"失忆"的：不知道做到哪、卡在哪、下一步做什么、哪些坑已经踩过。
本技能把当前状态固化成**单一权威文件**，让新会话读一遍就能接手，不用重述历史。

## 能力

- **重写而非追加**：产出单一权威状态文件，不写流水账（流水账交给 memory）
- **覆盖前先归档**：旧版自动存到 `Back Dialogue/archive/TIMEOFF-YYYYMMDD-HHMM.md`，保留最近 3 份
- **遵从项目规范**：项目若自带备份规范（如 `Back Dialogue/备份对话.md`），严格按其约定执行（含"增量合并、字节数不得缩减"这类硬约束）
- **交付前可执行校验**：路径存在性、敏感信息正则扫描、结构校验（卡点唯一 / 无重复标题 / 无冲突状态）

## 产出结构（默认 8 段）

1. 当前任务与目标
2. 当前权威状态（环境事实 / 产物清单 / 已确认结论）
3. 当前卡点（**只留一个**）
4. 下一步执行顺序
5. 必须保持的决策与安全边界
6. 不要再犯的错误（踩坑清单）
7. 需要用户 / 外部确认的事项
8. 接管提示（固定话术）

## 安装

把整个目录复制到用户级技能目录，然后重启 WorkBuddy：

- **Windows**：`%USERPROFILE%\.workbuddy\skills\session-handoff-backup\`
- **macOS / Linux**：`~/.workbuddy/skills/session-handoff-backup/`

```bash
# macOS / Linux
git clone <repo-url> ~/.workbuddy/skills/session-handoff-backup
```

## 使用

在对话里说任一句即可触发：

- 「备份对话」「写交接文档」「更新 TIMEOFF」
- 「会话太长了，开个新的」「保存上下文给下次会话」

新会话接管时，第一句话只说：

> 先读TIMEOFF.md，以实现跨对话的上下文接管

## 与 memory 的分工

| | `TIMEOFF.md`（本技能产出） | `.workbuddy/memory/YYYY-MM-DD.md` |
|---|---|---|
| 视角 | 下一个会话怎么接管 | 今天做了什么 |
| 写入方式 | 整体重写 / 增量合并 | 只追加 |
| 保留 | 单一权威的当前状态 | 历史流水与演进 |
| 篇幅 | 精简（≤500 行） | 不限 |

两者互补，不互相替代。
